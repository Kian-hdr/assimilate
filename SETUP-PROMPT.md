- Main skill: https://github.com/Kian-hdr/assimilate/tree/main/skills/assimilate
- REA software and bundled reverse-engineer-anything skill: https://github.com/morluto/rea
- Official Ghidra software: https://github.com/NationalSecurityAgency/ghidra
- Community Ghidra headless skill: https://github.com/mitsuhiko/agent-stuff/tree/0865c849befd2021490679f96a8dee58c84ac857/skills/ghidra

Use Assimilate as the main skill. When I say "Assimilate software", it should select and load the linked REA/Ghidra guidance, investigate the supplied software, and carry authorized findings into my destination project and its acceptance checks. Do not require me to invoke the supporting skills separately.

1. Inspect first. Read the Assimilate README, full skill, investigation adapter and docs/rea-setup.md. Check installed versions, the actual agent host, skill directories and relevant configuration. Inspect upstream instructions and scripts before running them. Preserve existing installations and unrelated settings. Reuse a compatible working stack; prepare recoverable backups before replacing meaningful files. Do not downgrade an existing stack merely to match these examples.

2. Install Assimilate with the host's supported skill installer. For Codex, resolve its installed skill-installer helper and use repository Kian-hdr/assimilate, path skills/assimilate. Install the Ghidra skill alongside it using repository mitsuhiko/agent-stuff, ref 0865c849befd2021490679f96a8dee58c84ac857, path skills/ghidra. Set ASSIMILATE_GHIDRA_SKILL_DIR if the host uses different skill roots. Ensure both Ghidra shell scripts are executable. Retain that upstream commit's Apache-2.0 LICENSE beside the Ghidra skill. It is a community skill, not an NSA-authored skill.

3. Install the runtime and engine. The tested baseline is rea-agents@6.3.0 with its bundled reverse-engineer-anything skill v34, Ghidra 12.1.4 and full OpenJDK 21. REA6.3.0 requires Node ^22.19.0 || ^24.11.0 || >=26.0.0. If Node/npm is missing or unsupported, install a compatible runtime through the platform's supported package manager or official distribution. On macOS with Homebrew, use brew install ghidra openjdk@21, then npm install --global rea-agents@6.3.0 when no suitable REA is installed. Verify the version Homebrew supplies against REA's actual supported Ghidra versions. If incompatible, use the official pinned Ghidra12.1.4 release ZIP and SHA-256 documented in docs/rea-setup.md, rather than changing version requirements. On another platform, follow the selected release's supported installation route and verify its native decompiler and full JDK compatibility. Keep runtime and bundled skill aligned; never install REA's repository-main skill over an older runtime independently.

4. Connect the actual agent. On macOS, resolve and export GHIDRA_INSTALL_DIR to the engine root (Homebrew formula: $(brew --prefix ghidra)/libexec), GHIDRA_HOME to the same root, and JAVA_HOME to the full JDK (Homebrew: $(brew --prefix openjdk@21)/libexec/openjdk.jdk/Contents/Home). For Codex, inspect rea setup --client codex --dry-run --format json, then apply that same scope with rea setup --client codex --yes. This installs REA's matching upstream skill and registers its MCP server. For another supported agent, substitute the actual supported client ID. Do not configure every detected agent. Ensure the saved registration includes the resolved Ghidra/Java environment; terminal exports alone do not configure a desktop MCP process. Keep REA license notices outside checksum-managed skill files. Do not install paid engines or unrelated provider tools.

5. Verify the connection and both Assimilate routes. Run scoped readiness with rea doctor --client codex --provider ghidra --skill --format json in the resolved environment, and a separate rea mcp doctor --format json. Resolve installed Assimilate and run its scripts/investigate.sh helper in rea and ghidra modes. Compile a small agent-authored fixture in a temporary directory using an existing compiler, recover a known function through REA/Ghidra, and export decompiled code through the Ghidra skill. Confirm the expected behavior, matching artifact identity and a clear missing-file failure; avoid unrelated installed applications. Close owned sessions and preserve useful test evidence. Validate skills and relative links. A setup/doctor pass alone is not a decompilation test.

6. Verify live use separately. If registration is new, reconnect or restart the agent as required, then check actual REA tools and Ghidra provider availability in that live session. If restart cannot be performed during this task, complete CLI verification and state the exact remaining live-connection step; do not claim live MCP passed. Skills become discoverable on a subsequent turn according to the host. Do not repeat setup when the only gap is session reload.

Complete the authorized installation, configuration and safe fixture checks without repeated discretionary approval. Respect platform authentication controls and my explicit constraints. Keep credentials, private binaries and machine configuration out of public repositories. Do not publish, send messages, launch a production target or perform network capture as part of setup.

Finish with the installed versions/locations, confirmed skill discovery, CLI and live MCP results, any exact remaining gap, and update/removal instructions. Keep the evidence limits clear: these checks prove bounded setup routes, not reconstruction of every application. Once configured, I should be able to say "Assimilate software" with a source and desired destination/capability, and let the main skill coordinate the tools.
